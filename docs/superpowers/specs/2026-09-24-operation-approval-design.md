# MiniClaw 危险操作审批设计

日期：2026-09-24

## 背景与目标

MiniClaw 当前为 Agent 提供 `read`、`edit`、`write` 和 Windows `powershell` 等工具。用户希望读取文件保持顺畅，但文件修改和 PowerShell 命令必须先经过人工确认，避免 Agent 在未授权时改变项目或执行命令。

本功能是应用内权限层，不是 Windows 管理员权限或文件系统 ACL。安全边界必须位于后端工具执行前，不能只靠前端隐藏按钮或展示提示。

## 已确认的产品规则

- `read` 直接执行，不需要确认。
- `edit`、`write`、`powershell` 每次执行前都进入审批流程。
- 审批卡片提供三个决定：
  - 仅允许这一次；
  - 允许本次任务后续操作；
  - 拒绝。
- “本次任务”定义为一次 Agent 回合：从用户发送一条消息开始，到该回合 `agent_settled`、失败、中止或 Run 关闭为止。
- 回合结束后，任务级授权立即失效；下一条消息重新审批。
- 请求来自飞书且没有可用桌面审批端时，危险操作默认拒绝，并由 Agent/桥接层返回“需要在桌面客户端确认”的可理解提示。
- 审批等待超时默认拒绝，不能无限挂起。
- UI 只展示后端已收到的真实工具调用。底层工具通常逐个发出，因此不得为了视觉效果虚构“将修改 3 个文件”之类尚未知晓的数量。

## 方案选择

采用 pi coding agent 的扩展 `tool_call` 钩子进行执行前拦截。

未采用以下替代方案：

- 重写 `edit`、`write`、`powershell` 工具：虽然控制力更高，但会复制底层工具行为，并与依赖版本强耦合。
- 仅让模型先输出操作计划：计划可能与真实工具调用不同，不能构成安全边界。

执行前钩子能够拿到真实 `toolName` 和输入参数，并可通过返回 `{ block: true, reason }` 阻止执行，适合作为唯一可信的后端权限关口。

## 架构

### ApprovalManager

新增独立的审批管理器，职责包括：

- 为危险工具调用创建唯一审批记录；
- 保存 Run、回合、工具名称、经过清洗的参数摘要、创建时间和过期时间；
- 返回一个等待审批决定的 Promise；
- 接受一次性允许、任务级允许或拒绝决定；
- 管理每个 Run 当前回合的任务级授权；
- 在超时、回合结束、Run 中止或关闭时清理等待项；
- 发布审批创建、解决和过期事件。

审批状态为 `pending | allowed | denied | expired | cancelled`。同一个审批只能从 `pending` 转换一次，重复提交返回冲突错误。

### AgentRun 集成

创建 Agent Session 时，通过 `DefaultResourceLoader.extensionFactories` 注册内联权限扩展。扩展监听 `tool_call`：

1. `read` 或其他明确只读工具直接返回。
2. `edit`、`write`、`powershell` 首先检查当前回合是否已有任务级授权。
3. 已授权则直接返回；未授权则调用 `ApprovalManager.request(...)` 并暂停该工具调用。
4. 一次性允许或任务级允许返回 `undefined`，底层继续执行工具。
5. 拒绝、超时、无审批端或取消返回 `{ block: true, reason }`。

AgentRun 在每轮 prompt 开始时生成新的回合标识。监听 `agent_settled` 并在异常、中止、关闭路径中结束该回合，清除任务级授权和仍在等待的审批。

### 来源与审批能力

Prompt 请求需要携带来源元数据：`desktop | web | feishu`。桌面聊天客户端发送 `desktop`；飞书桥接发送 `feishu`。

只有存在活跃桌面审批连接时，危险调用才允许进入等待状态。飞书来源本身不提供批准能力；如果桌面审批端未连接，后端立即拒绝危险操作。如果桌面端在线，飞书触发的操作仍可在桌面端显示并由用户批准，审批卡片应明确标注来源为飞书。

为避免把普通 SSE 读连接误当作可审批端，桌面客户端需要显式注册审批能力，并通过短周期心跳维持在线状态。连接过期即视为没有审批端。

## API 与事件

新增接口：

- `GET /api/agent/approvals?runId=<id>&status=pending`：获取待审批记录。
- `POST /api/agent/approvals/:id/decision`：提交 `{ decision: "allow_once" | "allow_turn" | "deny" }`。
- `POST /api/agent/approval-clients/heartbeat`：注册或刷新桌面审批能力。

审批记录的公开数据包含：

- `id`、`runId`、`turnId`；
- `toolName`、`summary`、`details`；
- `source`、`status`；
- `createdAt`、`expiresAt`。

现有 Run SSE 流新增内部事件：

- `approval_requested`；
- `approval_resolved`；
- `approval_expired`。

前端以 SSE 事件实时更新卡片，同时在重连后调用待审批查询接口恢复状态，避免刷新页面后丢失确认入口。

## 参数展示与隐私

- `edit`：显示目标文件路径和修改摘要，不默认展示完整文件内容。
- `write`：显示目标文件路径和预计写入字符数，可展开查看内容预览。
- `powershell`：显示完整命令文本和执行目录。
- 后端保留执行所需原始参数，但公开 API 对超长内容做截断，并避免将环境变量值、令牌或已知密钥写入审批日志。
- 审批记录只保存在内存和 Run 事件日志中，不新增长期保存的敏感操作数据库。

## 前端交互

审批卡片插入聊天时间线，位置对应工具调用发生时间。卡片包含：

- 风险类型图标和标题；
- 真实文件路径或 PowerShell 命令；
- 来源和当前项目目录；
- “仅允许这一次”“允许本次任务”“拒绝”三个按钮；
- 等待、已允许、已拒绝、已超时等只读状态。

提交决定后立即禁用三个按钮，等待后端确认。网络失败时恢复按钮并显示错误，不得在前端乐观地标记为已执行。

“允许本次任务”旁显示说明：“仅当前这轮对话有效，回答结束后自动失效”。

## 错误处理与安全约束

- 默认拒绝：无法判断工具风险、审批管理器异常、审批端离线、超时和 Run 已关闭时均不执行危险工具。
- 后端校验审批记录所属 Run 和当前状态，不能批准过期或其他 Run 的操作。
- 同一回合允许并行存在多个待审批项；任务级允许生效后，可统一允许该回合尚未解决的危险调用。
- 用户拒绝后，只阻止该工具调用，不强制终止整个 Run；工具结果把拒绝原因反馈给模型，让其解释或改用只读方案。
- 中止 Run 会取消所有待审批项并唤醒等待 Promise，防止内存泄漏。
- API 的批准能力仅限本机应用现有信任边界；如果未来允许远程访问 API，必须增加身份认证与 CSRF 防护后才能开放审批接口。

## 测试策略

### 后端单元测试

- `read` 不创建审批并直接执行。
- `edit`、`write`、`powershell` 在批准前不会执行。
- 一次性允许只影响当前调用。
- 任务级允许覆盖当前回合后续危险调用。
- `agent_settled`、失败、中止和关闭后任务级授权失效。
- 拒绝、超时和审批端离线均返回阻止结果。
- 飞书来源在桌面端离线时默认拒绝。
- 重复决定、错误 Run、过期审批返回确定的 API 错误。
- 并行审批和清理不会留下未解决 Promise。

### 前端组件测试

- 待审批卡片展示正确工具、路径、命令和来源。
- 三个决定发送正确的 API 数据。
- 提交中按钮禁用，失败后恢复。
- SSE 解决事件把卡片切换为只读最终状态。
- 页面重连后能够恢复待审批记录。

### 集成验证

- 使用假工具确认未批准前没有文件或命令副作用。
- 允许后工具只执行一次。
- 从飞书触发写操作且桌面端离线时，操作被拒绝并得到清晰回复。
- 运行现有前后端测试、类型检查、lint 和构建，确保聊天与 IM 流程无回归。

## 不在本期范围

- Windows UAC 或管理员提权。
- 按目录、命令模式或工具永久记住授权。
- 飞书卡片内直接批准操作。
- 在模型执行前准确预测本轮将修改的全部文件。
- 多用户身份和远程审批。

## 验收标准

- 未收到后端批准前，`edit`、`write` 和 `powershell` 不产生副作用。
- 用户可以选择一次允许、当前回合允许或拒绝。
- 当前回合授权在回答结束后自动失效。
- 无桌面审批端时危险操作默认拒绝，飞书消息不会绕过权限层。
- 页面刷新或 SSE 重连不会永久丢失待审批操作。
- 所有新增测试与既有测试、类型检查、lint 和构建通过。
