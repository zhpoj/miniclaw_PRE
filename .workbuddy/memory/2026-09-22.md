## miniclaw_PRE —— 切换默认模型到 DeepSeek 的踩坑记录

项目是 MiniAgent(HTTP 服务, src 包 `@earendil-works/pi-coding-agent@0.86.1`),
`npm run start` → `node dist/index.js`,默认监听 3000(可用 `PORT=3100` 覆盖)。

### 关键结论:pi 的全局 profile 默认模型这样配才生效
`~/.pi/agent/settings.json` 必须**同时**写 `defaultProvider`(裸 provider 名)和
`defaultModel`(裸 model id,**不带** `provider/` 前缀),例如:
```json
{
  "defaultProvider": "deepseek",
  "defaultModel": "deepseek-v4-pro",
  "modelThinkingLevels": { "deepseek/deepseek-v4-pro": "medium" }
}
```
- `findInitialModel` 第 3 步条件 `if (defaultProvider && defaultModelId)`,二者缺一就跳过,
  落到"第一个有 key 的可用模型"(环境里有 ANTHROPIC_API_KEY 就会变回 anthropic)。
- `getModel(provider, id)` 用 `model.id === id` 精确匹配,所以 `defaultModel` 写成
  `deepseek/deepseek-v4-pro`(完整串)会查不到 → 回落 anthropic。必须裸 id。
- `modelThinkingLevels` 的 key 仍用 `provider/id` 完整格式。

### 鉴权
- pi 鉴权来自**环境变量**,不读 `auth.json`(实测 `~/.pi/agent/auth.json` 是空 `{}`,
  之前能跑 anthropic 是因为环境里有 `ANTHROPIC_API_KEY`)。
- DeepSeek 需要 `DEEPSEEK_API_KEY` 环境变量;`hasConfiguredAuth` 看 `configuredProviders`,
  即环境变量是否注入。占位 key 即可让模型"被选为默认",但真实推理必须真 key。
- 项目 **没接 dotenv**(src 无 `dotenv.config()`),`.env` 文件不自动加载,key 必须显式以
  环境变量方式在启动命令里带入。

### 验证方法(无需真 key 即可验证模型选择)
启动带占位 key:`DEEPSEEK_API_KEY=sk-dummy PORT=3100 node dist/index.js`,
`POST /api/agent/runs` 返回的 run 快照里 `model` 字段显示 `{provider:"deepseek",id:"deepseek-v4-pro"}`
即表示 profile 钉成功。
